# Interview Prism 长期错题本设计

## 1. 目标

为 Interview Prism 增加一个跨面试、长期维护的“面试错题本”。错题本用于保存用户输入或用户与 AI 共同整理后确认的最优回答，并提供 Markdown 阅读、目录跳转和结构化检索能力。

错题本是独立的长期资产，不占用每场面试固定输出的五份报告，也不改变五份报告的名称与职责。

## 2. 核心原则

1. 不自动收录报告中的最佳回答或 AI 草稿。
2. 新增、更新和删除都必须获得用户对本次具体操作的明确确认。
3. 一次操作只允许影响一个目标条目及其对应索引信息。
4. 非目标错题的正文和目录项必须逐字保持不变。
5. 结构化数据是事实来源，Markdown 是面向用户的可读投影。
6. 更新保留版本历史，删除采用可恢复的软删除。

## 3. 范围

### 3.1 包含

- 新增错题候选并展示确认预览。
- 确认后写入结构化数据和 Markdown。
- 更新指定错题的答案、题目、标签或验证状态。
- 删除指定错题，并保留审计记录和恢复能力。
- 按关键词、岗位、能力类型、场景、来源、验证状态或条目 ID 检索。
- Markdown 顶部按能力类型维护可点击目录。
- 保留每次更新的版本、来源、时间和关联面试。

### 3.2 不包含

- 不从五份面试报告自动采集答案。
- 不因生成新面试报告而自动修改错题本。
- 不自动合并看似相似的问题。
- 不自动覆盖旧版本。
- 不提供模拟面试逻辑。
- 不在本功能中改变现有五份报告的输出契约。

## 4. 文件与存储

### 4.1 结构化事实来源

错题本数据存储在现有 ledger 的 SQLite 数据库中，新增两类记录：

- `answer_notebook_entries`：条目的当前状态和稳定 ID。
- `answer_notebook_revisions`：每次新增、更新、删除和恢复的不可变版本快照。

条目 ID 使用稳定格式 `NB-0001`、`NB-0002`，创建后永不复用。

### 4.2 Markdown 投影

默认输出为 ledger 级长期文件：

```text
<data-dir>/interview-answer-notebook.md
```

该文件不复制到每场面试的五份产物目录中。用户可以通过配置覆盖输出位置，但一个 ledger 只维护一个正式错题本 Markdown。

## 5. 数据模型

每个错题条目包含：

| 字段 | 说明 |
| --- | --- |
| `entry_id` | 稳定唯一 ID，例如 `NB-0001` |
| `canonical_question` | 去除口语化表达后的标准问题 |
| `target_role` | 适用岗位 |
| `ability_type` | 能力分类，同时作为默认目录分组 |
| `scenario_tags` | 面试场景标签 |
| `original_problem_summary` | 原回答的主要问题 |
| `best_answer` | 经用户确认的当前最优回答 |
| `answer_source` | `user` 或 `co_created` |
| `source_session_ids` | 关联面试记录，可为空 |
| `validation_status` | `unvalidated`、`used_in_real_interview` 或 `real_validated` |
| `version` | 当前版本号，从 1 递增 |
| `created_at` | 首次收录时间 |
| `updated_at` | 当前版本更新时间 |
| `deleted_at` | 软删除时间，未删除时为空 |
| `content_hash` | 当前版本内容摘要，用于并发保护 |

版本记录保存完整快照、操作类型、确认内容摘要和时间，不依赖 Markdown 反向恢复数据。

## 6. 用户确认协议

### 6.1 两阶段操作

所有写操作都采用“预览后确认”：

1. AI 根据对话生成待执行操作预览。
2. 预览明确展示操作类型、条目 ID、将变化的字段和变化后的内容。
3. 用户明确回复“确认收录”“确认更新”“确认删除”或同等清晰表达。
4. 系统校验确认对应的预览仍然有效，再执行写入。

“帮我优化”“这个回答不错”“以后可以用”等模糊表达不构成写入授权。

### 6.2 确认有效性

每份预览生成一次性操作摘要，绑定：

- 操作类型。
- 目标条目 ID；新增时绑定待创建内容。
- 目标条目确认前的 `content_hash`。
- 待写入内容的摘要。

如果用户在确认前改变了待写内容，或目标条目已被其他操作更新，旧确认失效，系统必须重新展示预览并再次确认。

### 6.3 更新规则

修改已有最优回答也属于写操作，必须确认。确认后创建新版本，不覆盖或删除旧版本记录。

### 6.4 删除规则

删除预览必须展示条目 ID、标准问题和当前版本。确认后：

- 结构化数据标记为软删除。
- Markdown 删除该条目的目录项和正文区块。
- 版本历史保留删除事件，允许后续经确认恢复。

## 7. Markdown 结构与索引

### 7.1 索引区

文件顶部包含受控索引区：

```markdown
<!-- notebook-index:start -->
## 错题目录

### 产品设计
- [NB-0001 如何判断一个功能是否值得投入？](#nb-0001)
<!-- notebook-index:end -->
```

目录默认按能力类型分组。组内保持条目创建顺序，不因更新或重新渲染进行全局排序。

### 7.2 条目区

每个条目使用稳定边界：

```markdown
<a id="nb-0001"></a>
<!-- notebook-entry:start NB-0001 -->
## 如何判断一个功能是否值得投入？

- 条目 ID：NB-0001
- 适用岗位：产品经理
- 能力类型：产品设计
- 来源：共同整理
- 当前版本：v1
- 验证状态：尚未验证

### 原回答的主要问题

...

### 当前最优回答

...
<!-- notebook-entry:end NB-0001 -->
```

## 8. 精确更新与不变量

Markdown 更新器不得进行全文件格式化或无条件全量重写。

### 8.1 新增

- 在目标能力分类末尾追加一条目录项；分类不存在时追加新分类。
- 在文件末尾追加一个新条目区块。
- 不改变已有条目和已有目录项。

### 8.2 更新

- 只替换目标 `entry_id` 的正文区块。
- 题目和能力分类未变化时，不修改索引。
- 题目或能力分类变化时，只更新或移动目标目录项。
- 不重新排序其他目录项。

### 8.3 删除

- 只删除目标目录项和目标正文区块。
- 如果删除后能力分类为空，可以删除该空分类标题。
- 不改变其他分类和条目。

### 8.4 写入保护

写入前记录所有非目标条目区块及非目标目录项的摘要；写入后在内存中比较摘要。任何非目标内容发生变化时，放弃整个文件替换和数据库事务，并返回冲突错误。

数据库变更和 Markdown 文件替换必须作为一个逻辑操作完成：先在临时文件中生成目标补丁并完成不变量校验，再提交数据库事务并原子替换 Markdown。任一步失败都不留下半完成状态。

## 9. 检索能力

结构化检索支持：

- `entry_id` 精确查询。
- 标准问题和最优回答的关键词查询。
- 岗位、能力类型、场景标签筛选。
- 答案来源筛选。
- 实战验证状态筛选。
- 是否已删除筛选；默认不返回已删除条目。

自然语言查询由 Skill 转换为结构化筛选，例如：

```text
查一下错题本里和推荐策略有关的问题。
列出所有还没有经过真实面试验证的产品设计题。
打开 NB-0004。
```

检索是只读操作，不需要用户确认，也不得修改错题本。

## 10. 与现有 Skill 的集成

`SKILL.md` 增加“长期错题本”工作流，并明确：

- 五份面试报告生成完成后不得自动收录任何内容。
- AI 可以询问用户是否希望整理为错题候选，但不能把询问当作确认。
- 用户输入的最优回答和共同整理的答案使用相同确认协议。
- 每次成功操作返回条目 ID、版本和实际修改范围。
- 每次取消或确认失效都返回未写入说明。

README 增加错题本能力、示例指令和隐私说明，但不把错题本列为第六份面试报告。

## 11. 错误处理

| 场景 | 行为 |
| --- | --- |
| 未明确确认 | 不写入，继续保留预览或取消操作 |
| 确认内容与预览不一致 | 旧确认失效，重新展示预览 |
| 条目已被更新 | 停止操作，展示最新版本并重新确认 |
| 条目 ID 不存在 | 不写入，提示重新选择 |
| 重复问题 | 展示可能重复项，由用户决定新增还是更新 |
| Markdown 边界损坏 | 停止写入，不尝试猜测或全量修复 |
| 非目标内容摘要变化 | 回滚本次操作并报告保护性中止 |
| 数据库或文件写入失败 | 保持数据库和 Markdown 都处于操作前状态 |

## 12. 验收标准

1. 每场面试仍只输出既定五份 Markdown 报告。
2. 未确认时，新增、更新、删除均不会修改数据库或 Markdown。
3. 报告中的“最佳回答”不会自动进入错题本。
4. 用户确认新增后，结构化数据与 Markdown 同时出现一个新条目。
5. 用户确认更新后，目标条目版本递增，旧版本仍可追溯。
6. 用户确认删除后，目标条目从默认查询和 Markdown 中消失，但可恢复。
7. 新增、更新、删除前后，所有非目标条目正文逐字一致。
8. 除目标目录项及必要的目标分类标题外，其他目录内容逐字一致。
9. Markdown 目录链接可以跳转到稳定条目锚点。
10. 关键词与字段筛选可以返回正确条目，且不产生任何写操作。
11. 并发版本冲突会中止操作并要求重新确认。
12. Markdown 损坏或不变量校验失败时，不产生部分写入。

## 13. 测试范围

实现阶段应覆盖：

- 未确认、确认新增、确认更新、确认删除和确认恢复。
- 重复候选提示与用户选择。
- 题目不变更新、题目变化更新、跨能力分类移动。
- 非目标条目和目录项的逐字一致性。
- 结构化数据与 Markdown 的原子一致性。
- 过期确认和并发更新冲突。
- Markdown 边界损坏保护。
- 多条件检索与默认排除软删除记录。
- 现有五份报告契约的回归保护。
