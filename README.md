# Interview Prism

> 把散落在每场面试里的回答，变成可复盘、可积累、可验证的长期成长资产。

Interview Prism 是一个面向 Codex、Claude 等 AI Agent 的面试复盘 Skill。

它不只分析一场面试，而是帮助你持续完成三件事：

- 看清这一场面试答得怎么样。
- 发现多场面试中反复出现的能力问题。
- 把真正认可的最优回答沉淀进长期错题本，持续更新和验证。

```text
面试文字稿
    ↓
五份结构化复盘报告
    ↓
与 AI 讨论和优化关键回答
    ↓
用户确认后收入长期错题本
    ↓
在下一场真实面试中继续验证
```

## 一行安装

```bash
npx skills add https://github.com/Yixiao-Zhang1214/Interview-Prism-Skill
```

安装完成后，可以在 Codex 或 Claude 中直接发送面试文字稿，并说明：

```text
请使用 Interview Prism 分析这份面试文字稿。
```

## 核心能力

### 单场面试深度复盘

Interview Prism 会区分面试官和候选人的发言，提炼口语化问题，并结合候选人的真实回答给出有证据的判断。

分析重点包括：

- 哪些回答真正有效。
- 哪些回答偏题、空泛或缺少证据。
- 面试官为什么继续追问。
- 更好的回答结构和示范答案。
- 能力优势、风险和下一步练习重点。
- 基于现有证据，对面试结果给出鼓励但客观的预估。

### 每场面试固定输出五份报告

| 文件 | 内容 |
| --- | --- |
| `analysis.md` | 逐题分析、优点、问题、优化方向和示范回答 |
| `qa-original.md` | 提炼后的关键问题与候选人原始回答 |
| `ability-model.md` | 能力模型、评分、证据和能力快照 |
| `frequent-questions.md` | 高频问题、考察意图和准备建议 |
| `comparison.md` | 当前面试与此前真实面试的综合趋势报告 |

第五份 `comparison.md` 会综合当前及此前的真实面试。只有一场面试时，它会明确说明样本不足，不制造虚假的成长趋势。

结构化会话数据属于内部账本，不是第六份用户报告。

## 长期面试错题本

错题本是 Interview Prism 的核心长期能力。它独立于每场面试的五份报告，用来保存你真正认可、愿意在下一场面试继续使用的答案。

错题本可以记录：

- 你直接输入的最优回答。
- 你与 AI 讨论后共同整理的定稿。
- 原回答存在的主要问题。
- 适用岗位、能力类型和面试场景。
- 关联的真实面试记录。
- 当前答案版本和更新时间。
- 是否已经在真实面试中使用或验证。

### 不自动收录

Interview Prism 不会自动把报告中的“最佳回答”写进错题本，也不会把未经确认的 AI 草稿当成正式答案。

所有新增、更新、删除和恢复操作都遵循相同流程：

```text
生成操作预览
    ↓
展示具体变化
    ↓
等待用户明确确认
    ↓
只修改目标错题
```

以下表达不会触发写入：

```text
帮我优化一下。
这个回答不错。
以后可以这样答。
```

只有明确确认后才会执行，例如：

```text
确认收录。
确认更新 NB-0004。
确认删除 NB-0004。
```

### 保证其他错题不变

每道错题都有稳定 ID，例如 `NB-0001`。

执行一次操作时，Interview Prism 只允许修改：

- 目标错题的正文区块。
- 目标错题对应的目录项。
- 必要时，目标错题所属的分类标题。

其他错题及其目录项必须逐字保持不变。系统发现非目标内容发生变化时，会停止写入，而不是尝试自动修复或全量重排。

### 目录与检索

错题本会生成可点击的 Markdown 目录，并支持按以下条件检索：

- 问题关键词
- 条目 ID
- 目标岗位
- 能力类型
- 面试场景
- 答案来源
- 实战验证状态

你可以直接说：

```text
查一下错题本里和推荐策略有关的问题。
列出所有还没有经过真实面试验证的产品设计题。
打开 NB-0004。
```

### 版本与删除保护

- 更新答案会创建新版本，不覆盖历史版本。
- 删除采用可恢复的软删除。
- 过期确认不能继续执行。
- 确认后目标内容发生变化时，系统会要求重新确认。
- 同一问题疑似重复时，只提供提醒，不自动合并。

## 推荐使用方式

### 复盘一场面试

```text
请分析这份面试文字稿，生成完整的五份报告。
关键问题请去除口语化表达，并区分面试官问题和候选人回答。
```

### 整理一个错题候选

```text
把刚才讨论的回答整理成错题候选，先展示完整内容，不要直接收录。
```

### 收录用户自己的答案

```text
这是我确认过的最优回答。请生成收录预览，答案来源标记为用户提供。
```

### 更新已有答案

```text
把刚才确认的版本用于更新 NB-0004，先展示具体变化。
```

### 删除或恢复

```text
准备删除 NB-0004，执行前让我确认。
恢复 NB-0004，先展示恢复预览。
```

## 一次面试如何变成长期积累

Interview Prism 的完整闭环不是“生成报告后结束”，而是：

1. 输入一场真实面试文字稿。
2. 查看五份报告，定位最值得改进的问题。
3. 与 AI 讨论答案结构、证据和表达方式。
4. 由你决定哪一版可以成为正式答案。
5. 明确确认后收入错题本。
6. 下一场面试后继续更新验证状态和答案版本。
7. 通过 `comparison.md` 观察多场面试中的能力变化。

这样，每场面试不再是一份孤立的复盘文档，而会成为个人面试知识库的一部分。

## 文件与数据

每场面试的报告文件采用统一前缀，例如：

```text
IP-R-20260818-1359-analysis.md
IP-R-20260818-1359-qa-original.md
IP-R-20260818-1359-ability-model.md
IP-R-20260818-1359-frequent-questions.md
IP-R-20260818-1359-comparison.md
```

长期数据目录包含：

```text
library.db                         # 结构化账本、历史版本和确认记录
interview-answer-notebook.md       # 可阅读、可点击跳转的长期错题本
```

结构化数据是事实来源，Markdown 是面向用户的阅读版本。重新生成单场面试报告不会自动修改错题本。

## 设计原则

- **忠于原文**：判断必须能够回到真实面试证据。
- **区分角色**：面试官的问题不会被误判为候选人的最佳回答。
- **客观鼓励**：既指出进步，也诚实表达证据不足和风险。
- **问题提炼**：关键问题去除口头语，但不改变原始考察意图。
- **用户决策**：AI 可以建议，正式答案必须由用户确认。
- **长期可追溯**：答案更新保留版本，删除可以恢复。
- **最小修改**：操作一条错题时，不触碰其他错题。
- **本地优先**：面试数据、报告和错题本保存在本地工作目录。

```bash
python3 scripts/test_answer_notebook.py -v
python3 -m unittest discover -s scripts -p 'test_interview_report.py' -v
```

当前测试覆盖：

- 五份报告输出契约
- 多场面试综合报告
- 未确认不写入
- 确认新增、更新、删除和恢复
- 非目标错题保持不变
- 版本冲突和重复确认保护
- 错题本检索与重复问题提醒

## 适用场景

- 产品经理、AI 产品经理等岗位的真实面试复盘
- 多场面试能力趋势分析
- 高频问题准备和回答迭代
- 个人最优回答知识库建设
- 求职周期中的长期成长记录

Interview Prism 不包含模拟面试逻辑。它专注于真实面试材料的复盘、比较和长期沉淀。
