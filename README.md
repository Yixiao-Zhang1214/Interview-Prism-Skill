# Interview Prism

把真实面试文字稿，变成有证据、可行动、能持续积累的面试复盘。

Interview Prism 是一个面向 Codex 和 Claude Code 的面试复盘 Skill。你只需要上传或粘贴真实面试文字稿，它会帮你提炼关键问题、分析回答表现、识别面试官可能的顾虑，并把每一次面试沉淀进个人成长账本。

它不只回答“这场表现怎么样”，还会帮助你理解：

- 面试官真正想考察什么
- 哪些回答形成了明确加分
- 哪些地方证据不足或容易被追问
- 下一次应该如何调整表达和思考方式
- 多场面试中，哪些问题正在改善，哪些风险反复出现

## 你会得到什么

### 单场面试复盘

Interview Prism 会还原面试中的问答关系，并将口语化、重复的问题提炼成清晰的标准问题。每个重点回答都会包含：

- 真正考察点
- 答得好的地方
- 没有答够的地方
- 下一次怎么答
- 模拟面试官可能的第一反应和剩余顾虑

所有判断都尽量引用原始文字证据。推测内容会明确标注，不会冒充真实面试官结论。

### 多场综合分析

当你积累多场真实面试后，Interview Prism 会把它们放进同一个成长账本，帮助你观察：

- 能力表现的前后变化
- 反复出现的关键问题
- 持续存在的证据缺口
- 已经改善和尚未改善的成长任务

只有一场面试时，系统只生成初始快照，不会制造虚假的“趋势”。

## 每场固定生成 5 个文档

| 文档 | 用途 |
|---|---|
| `analysis.md` | 完整面试复盘，包括结论、能力快照、关键问题和成长任务 |
| `qa-original.md` | 按时间顺序整理的原始问答，方便回看上下文 |
| `session.json` | 可验证、可迁移的结构化会话数据 |
| `ability-model.md` | 当前能力模型及已有面试中的表现变化 |
| `frequent-questions.md` | 已出现的问题、考察点和重复证据缺口 |

能力快照直接以 Mermaid 图表写入主报告，不再额外生成图片附件。

## 使用流程

1. 上传 Markdown、TXT 文字稿，或直接粘贴面试内容。
2. Interview Prism 识别说话人、时间戳和问答关系。
3. 关键问题被提炼为简洁标题，原始措辞继续保留用于证据回查。
4. 系统生成单场复盘和固定 5 个文档。
5. 后续继续上传真实面试，系统更新成长账本和多场综合报告。

你不需要提前删除口语词，也不需要手工区分问题和答案。只要文字稿中能够大致识别不同说话人，Interview Prism 就可以开始整理。

## 分析原则

### 证据优先

评价必须能回到原始文字。没有数据、没有结果或无法确认的内容，会被明确标记为信息缺口。

### 事实与推测分开

候选人说过的话、面试官说过的话和系统推测的面试官反应属于不同信息层级，不会混写。

### 鼓励改进，但不回避问题

报告以帮助下一次表现更好为目标，同时保持客观，不把鼓励写成无依据的正面结论。

### 不制造趋势

单场记录不代表稳定能力；两场记录只能描述变化，样本足够后才适合讨论重复模式。

## 隐私说明

Interview Prism 默认处理你主动提供的本地文字稿和本地账本。是否上传、分享或发布报告，由你自己决定。

面试文字稿可能包含姓名、公司、岗位和招聘信息。公开报告前，请检查并删除不适合披露的内容。

## 常见问题

### 需要先整理文字稿吗？

不需要。直接上传原始转写即可。系统会保留原文，并单独生成适合阅读的关键问题标题。

### 会判断我是否一定通过吗？

不会。Interview Prism 可以给出有边界的模拟倾向，但不会把推测写成真实招聘结果。

### 为什么要保留原始问答？

为了让每个判断都能回到证据，也方便你发现转写错误或理解上下文。

### 可以分析多场面试吗？

可以。持续使用同一个真实面试账本，即可生成跨场问题、能力变化和成长任务报告。

## 适合谁

- 正在找实习或校招机会，希望系统复盘真实面试的人
- 经常遇到项目深挖、产品设计和数据追问的产品经理候选人
- 希望长期观察面试表现，而不是只获得一次性建议的人
- 需要保留原始证据、避免泛泛评价的求职者

从第一份真实面试文字稿开始，让每一次面试都成为下一次进步的证据。
