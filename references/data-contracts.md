## Source and Lineage Rules

- `session.id`, stable entity IDs, timestamps generated by code, and `source_type` are deterministic fields.
- `source_type` is exactly `real` or `mock` and is immutable after session creation.
- Transcript, JD, notes, and actual feedback retain their original source labels.
- Model stages propose relationships and semantic fields; code validates and creates permanent IDs.
- `schema_version` starts at `1`. Reject unknown major schema versions.

## Session Exchange Package

Use this shape for local import or portable download:

```json
{
  "schema_version": 1,
  "session": {
    "id": "int_20260810_ab12cd",
    "source_type": "real",
    "occurred_at": "2026-08-10T14:00:00+08:00",
    "company": "Example",
    "role": "Senior Product Manager",
    "round": "Hiring Manager"
  },
  "source": {
    "input_type": "text",
    "host_transcribed": false,
    "has_exact_timestamps": false,
    "has_speaker_labels": true,
    "content_hash": null,
    "blocks": [
      {"block_id": "blk_001", "text": "immutable source block"}
    ]
  },
  "job_context_items": [],
  "segments": [],
  "qa_chains": [],
  "other_dialogue_segment_ids": [],
  "question_analyses": [],
  "assessments": [],
  "simulated_reactions": [],
  "session_review": {},
  "growth_tasks": [],
  "knowledge_candidates": [],
  "warnings": [],
  "generation": {
    "prompt_versions": {},
    "model": null,
    "generated_at": null
  }
}
```

Fields without evidence use `null` or an empty array; do not fabricate placeholder facts. `generated_at` is filled by code or the host clock, not guessed by the model.

## Segment Contract

```json
{
  "segment_id": "seg_001",
  "sequence_no": 1,
  "source_block_id": "blk_001",
  "start_char": 0,
  "end_char": 18,
  "speaker_role": "interviewer",
  "speaker_label": "Speaker 1",
  "event_type": "question",
  "text": "source text sliced by code",
  "start_time": null,
  "end_time": null,
  "confidence": "high",
  "uncertainty_reasons": []
}
```

Allowed `speaker_role`: `interviewer`, `candidate`, `unknown`.

Allowed `event_type`: `opening`, `question`, `answer`, `follow_up_question`, `follow_up_answer`, `interviewer_context`, `candidate_question`, `interviewer_answer`, `closing`, `other`.

The model never supplies the final `text` in P01. Code copies it from the source block using a zero-based, left-closed/right-open character range. Validate ranges before ID creation.

When `source.blocks` is present, local import requires every segment to provide a valid source block and character range, rejects overlaps, and verifies `segment.text == block.text[start_char:end_char]`.

## Question-Chain Contract

```json
{
  "qa_chain_id": "qa_001",
  "sequence_no": 1,
  "direction": "interviewer_to_candidate",
  "turns": [
    {"turn_type": "question", "segment_ids": ["seg_001"]},
    {"turn_type": "answer", "segment_ids": ["seg_002"]},
    {"turn_type": "follow_up_question", "segment_ids": ["seg_003"]},
    {"turn_type": "follow_up_answer", "segment_ids": ["seg_004"]}
  ],
  "answer_status": "complete",
  "mapping_confidence": "high",
  "uncertainty_reasons": [],
  "warnings": []
}
```

Allowed directions: `interviewer_to_candidate`, `candidate_to_interviewer`.

Allowed answer status: `complete`, `partial`, `missing`.

Every referenced segment must exist. Within one session, a segment enters exactly one question chain or `other_dialogue_segment_ids`; duplicate and unassigned segments make the import invalid.

## Growth Task Contract

```json
{
  "task_id": "task_001",
  "source_type": "real",
  "source_session_id": "int_xxx",
  "source_qa_chain_ids": ["qa_001"],
  "title": "Rebuild the project outcome evidence",
  "task_type": "case_material",
  "root_cause": "case_evidence",
  "steps": ["Locate the baseline, launch date, and metric window"],
  "acceptance_criteria": ["Explain the metric, baseline, change, and attribution limit in 45 seconds"],
  "real_validation_condition": "A later real interview answer receives level 4 or above on data_and_outcome_evidence",
  "status": "open",
  "suggested_duration_days": 7,
  "priority": "high"
}
```

Allowed task types: `knowledge`, `case_material`, `answer_rebuild`, `compression`, `pressure_follow_up`, `real_world_validation`.

Allowed task statuses: `open`, `in_progress`, `training_passed`, `waiting_real_validation`, `real_validated`, `archived`.

A mock session may create or update through `waiting_real_validation`; it cannot set `real_validated`.

## Local Persistence Rules

The manager creates `library.db` in a user-selected directory outside the Skill. It uses canonical SHA-256 input fingerprints, SQLite transactions, foreign keys, and soft deletion.

The supported CLI contract is:

```text
init, import, list, render-qa, profile, delete, restore
```

Never let the model issue arbitrary SQL. Never silently overwrite an existing session. Reports are derived output and can be rebuilt; original source material is not rewritten.
